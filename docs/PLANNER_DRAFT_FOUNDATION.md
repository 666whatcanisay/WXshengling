# 可信目标与可恢复草案 · 阶段1

2026-11-06，D036。用户在D035路线之后要求“推进开发/继续”，本轮仅实现阶段1。**本地完成；用户明确批准后，app-node24三文件已部署并下载核对，用户已通过微信生成/编辑保存/重编译恢复的正常主链，真实并发/断网异常尚未云端实测。** 后续阶段继续单独对齐。

## 用户能看到什么

- 保留 AI → AI规划师的聊天与任务编辑弹窗。寒暄不再直接占用目标，用户明确换目标时清除旧预算/基础等信息；不从助手回复填写用户要求。
- 新增“查看草案 / 保存草案 / 恢复云端稿”，并显示模型生成或本地规则模板、已保存版本/本机未保存/失败/冲突。云端恢复替换当前稿前先备份，提供“恢复本机备份”。
- 可以只说目标就生成；未说明的周期、每日投入和基础显示为草案建议/待核对信息，不编造成用户已确认。
- 生成成功后服务器尝试自动保存草案版本；之后的手动编辑先按账号保存在本机，点击“保存草案”才写云端。退出后重新进规划师或审核师能读取当前云端草案。保存响应不明时保留同一请求重试。
- 审核师展示云端版本或本机快照，仍未进行真实AI审核，不新增审核门禁。
- 原有确认发布接口继续创建正式目标/任务；草案保存本身不创建这些记录、不增加奖励。发布成功后的草案归档失败不会改报“发布失败”。

## 技术与数据

原生 JS/WXML/WXSS + 现有 wx-server-sdk 2.4.0/Node24；不引入新SDK或依赖。复用 `ai_plans` 集合，使用事务、预期版本比较和确定性请求ID。事务仅按doc读取，符合[官方事务限制](https://docs.cloudbase.net/database/transaction)；SDK实际返回形状以安装版本的隔离试验为准。

| 对象 | 主要内容 |
|---|---|
| `plan_generation` | 原两步生成的记录，新记录标明类型；旧无kind记录继续兼容 |
| `planner_workspace` | 按服务端OPENID生成的工作区ID，当前版本、草案指针、最多40条会话与用户要求 |
| `planner_draft_version` | 不可变草案版本、来源生成ID、稳定任务ID、要求版本/来源、内容指纹、未确认假设 |
| 本机工作副本 | 账号隔离的未保存编辑、原保存请求、编辑序号；替换云端稿前另存备份 |

三个新增接口为 `getPlannerDraft` / `savePlannerDraft` / `clearPlannerDraft`，身份沿用 `cloud.getWXContext().OPENID`，不接受客户端指定别人的owner。既有 `ai_plans` ADMINONLY权限保留，没有新增集合/索引/直连数据库。

`plannerContext.js` 是前后端纯解析规则的唯一源码；部署副本由 `tools/sync-planner-context.cjs` 同步，`npm test` 先校验字节一致。要求只来自用户消息或主动编辑，包含来源消息ID/引用/修订号；模型建议单列。规则提取不等于完整自然语言理解，未识别的信息可继续明确表达/编辑，后续语义整理也必须保留来源。

草案允许临时空任务/未填数字；正式发布仍执行原有完整校验。保存请求同ID同内容返回原版本，不同内容拒绝；旧版本无法覆盖新稿。清空工作区推进版本并保留历史，阻止旧生成结果重新成为当前稿。
