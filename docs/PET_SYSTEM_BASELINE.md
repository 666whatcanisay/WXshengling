# 宠物系统基线与形象升级档案

核查日期：2026-11-08（Asia/Shanghai）。用于今后升级形象、复查规则和兼容旧宠物。当前依据是本地小程序、`cloudfunctions/app` 源码、11 月 4 日留存的云图，以及本轮离线探针。已发布小程序可能走旧云函数，本文未查询最新云端记录或真机效果。旧审阅保留在 [PET_REVIEW](PET_REVIEW.md)，宠物聊天联动另见 [PET_INTEGRATION_READINESS](PET_INTEGRATION_READINESS.md)。

## 1．从用户操作到数据变化

| 用户路径 | 当前行为 | 主要入口 |
|---|---|---|
| 森林 → 领蛋、换蛋 | 森林蛋、家园蛋、荒野蛋三类；正常领蛋入口限制最多 3 只在养，最多 1 颗未孵化。未孵化蛋可指定或随机更换类型，保留已投入成长。蛋用花纹、色彩与动画展示。 | `createEgg`、`refreshEgg`、`_buildEggAppearance` |
| 签到、打卡 → 成长池 | 签到给用户 10 XP，首页首次签到再调用 `hatchProgress(checkin)`，加 5 点宠物侧成长。任务打卡事务把任务奖励同时计入用户总 XP 与成长池。首页和目标列表还会在首次有效打卡后调用 `hatchProgress(complete_goal)`，额外计入 10 点，优先自动拨给蛋，否则拨给首只在养宠物；没有宠物时留池。目标详情、记录页及补签卡走任务结算，未接这一步自动拨付。 | `dailyCheckin`、`taskCheckin`、`hatchProgress`；首页、目标、详情、记录页 |
| 森林 → 泉水灌注、孵化、进化 | 把池中成长分给指定宠物；100 孵化，300 少年，600 成年，1200 完美形态。自动成长和手动灌注共用孵化函数。孵化生成物种、四维属性、独立稀有度、颜色档、天赋、随机性格、亲密度 50、心情和成长记录。成长值跨阶段的部分路径会给属性奖励、记录或触发事件。 | `allocatePool`、`performPetHatch`、`generateStageUpBonus` |
| 森林 → 喂食、玩耍、抚摸 | 直接互动写宠物经验、亲密度、心情和日志。喂食 +10 经验/+2 亲密，玩耍 +15/+4，当前抚摸传 `pat`，实际落到 +5/+2 的默认分支。亲密度上限 1000，档位阈值 0/200/400/700/900。 | `petInteract`、`BOND_LEVELS` |
| 森林 → 背包、礼包 | 普通／高级饲料加 10／30 宠物经验与成长值；药水当前为 90% 加 30–50 经验与成长、10% 加一项属性；补签卡完成今日一条待办。新手礼包 +800 成长池，儿童节礼包一次给四种道具各 20，当前后端按领取标记判断，无节日日期条件。 | `_useFeed`、`_useGrowthPotion`、`_useMakeupCard`、`useBackpackItem`、`claimStarterXp`、`claimChildrenDayGift` |
| 森林 → 档案、改名、性格、觉醒 | 档案显示属性、天赋、亲密度、心情、性格和成长记录。支持孵化后写性格描述、进化后写性格期望。觉醒按存储阶段准入，写觉醒标记和带前缀的名字，没有独立觉醒图片路径。 | `buildDisplayPet`、`openProfile`、`setPetPersonality`、`setPersonalityPrompt`、`awakenPet` |
| 图鉴、历史、放行 | 「我的」图鉴有在养、历史、最稀有宠物。森林有物种收集图鉴；已放行的物种仍计入曾拥有。放行为软删除，写 `deleted_at`，同时把 `is_hatched` 置 false，保留物种、名字、阶段等历史字段。 | `petCollection`、`deletePet`、`petDetail` |
| 事件、来信和聊天 | 连签与阶段等有宠物事件模板，森林有未读提醒。另有来信查询、已读和收藏后端，统一前端入口未完整接通。AI 页聊天主要使用关键词和预设回复，可记录一次 `chat` 互动。性格描述、期望和 `chat_context` 已有字段，长期对话与跨 Agent 联动仍待独立设计。 | `checkAndGeneratePetEvent`、`checkLetters`、`markLetterRead`、AI 页 `sendChat` |
| 后台宠物管理 | 可分页查看和编辑阶段、等级、宠物经验与心情。本地新版在切换阶段时同步成长值，保留同阶段进度和原孵化流程。 | `adminListPets`、`adminEditPet`、管理页 `savePetEdit` |

代码主入口：[森林模板](../miniprogram/pages/pets/pets.wxml)、[森林页面逻辑](../miniprogram/pages/pets/pets.js)、[云端处理器](../cloudfunctions/app/index.js)、[客户端 API](../miniprogram/utils/cloudApi.js)。签到与任务奖励的数字属于当前本地源码口径。

## 3．数据合同与兼容重点

| 层 | 当前字段、来源与注意事项 |
|---|---|
| 身份与收藏 | `pets._id` 是记录身份，返回常映射成 `id`。`species` 是资源和收藏键，`name` 可改也可被觉醒加前缀。资源升级保留两者，按物种 ID 找图。归属从服务端微信身份取得。历史状态以 `deleted_at` 优先。 |
| 蛋与阶段 | 现代外观依赖 `is_hatched`、`egg_type`、`growth_value`。旧数据保留 `stage`、`egg_stage`、`hatch_progress`。营地立绘按成长值选，图鉴和部分操作仍读存储 `stage`。旧记录缺成长值时不能把补上的 0 当成真实零成长，也不能因放行标志误画成蛋。已孵化但成长值不足 100 会算出 EGG，阶段选图返回空，应作为兼容样本。 |
| 四种数值 | `users.total_xp` 是用户总经验。池的 `growth_pool` 是余额，`total_earned` 是累计进池；宠物的 `growth_value` 决定立绘阶段，`experience/level` 是另一套宠物经验和等级。它们不能互相补值或重新换算。 |
| 稀有度与颜色 | `rarity` 普通／稀有／史诗／传说，孵化概率 70/20/8/2。独立的 `color_tier` 普通／稀有色／异色为 92/6/2，另存 `color_label` 和旧布尔 `is_shiny`。旧异色只有布尔时要保留判定，不能用 API 填的 `normal` 覆盖历史含义。 |
| 属性与陪伴 | 当前四维为 `vitality/wisdom/luck/resonance`，历史还可能有 `attribute_type` 或其他键，`attributes` 可能为 null。保留现有属性、`bond`、`mood` 与旧 `status`、性格、天赋、称号、觉醒标志、时间和用户自定义内容。 |
| 记录 | `growth_records` 与 `pet_events` 是宠物记录内的数组；`growth_logs` 是账号级流水，不能按文案推断属于哪只宠物。来信走 `pet_letters`。保留原记录和已读标记。 |
| 接口投影 | `listPets` 返回当期大部分外观字段；`petCollection` 在养列表仍带 `hatch_progress`，未透传 `growth_value`、颜色档；历史投影更窄。图鉴若将来接新立绘，先决定是否补最少的只读投影字段，保持旧响应结构。 |

外观链：`listPets → buildDisplayPet → getPetAppearance → getSpeciesImagePath → pet_assets_config → 云图／Emoji 兜底`。首页轮播直接使用现有 Emoji；「我的」图鉴也预计算 Emoji；营地使用立绘与颜色滤镜；素材预览页的“60”是配置数量。首入营地调用 `resolvePetImageUrls`，局部刷新未完整复用它。资源管线文档曾写 180 张三色图，运行配置实际读 `pets/<species>/<stage>_thumb.png`，同阶段三色共用一个路径。旧 [管线说明](../miniprogram/assets/pets/species/PIPELINE_MODULE_SPEC.md) 用于理解历史产物，升级前以 [实际映射](../miniprogram/utils/pet_assets_config.js) 为准。

## 5．形象升级的边界与验收

1. **按现有记录兼容。** D051 明确无需额外归档旧图版本。已有宠物身份、历史数据及运行中的资源回退路径继续兼容。候选按物种、阶段和颜色档验收透明边缘、显示与回退。首页宠物卡沿用已认可的轮播样式。
2. **先用猞猁做四阶段对照，再补明确错图。** 让耳簇、脸型、斑纹贯穿四阶段，变化落在比例、体态、毛量和少量装饰。以森林深绿底、营地主图和小缩略图检查可辨性；先验透明边缘与身份连续，再决定色档和稀有度光效。候选版先在本地或预览页选看。
3. **改的是映射和显示。** 优先沿用原生 WXML/WXSS、外观构建器与现有云图解析。版本映射按既有 ID 查图，候选缺图优先回退同物种、同阶段旧素材；确知是跨物种错图时使用合适的物种图标兜底。不要重抽物种、覆盖旧外观字段、迁移宠物记录或重新结算成长。
4. **兼容验收。** 覆盖新蛋、旧蛋只有 `hatch_progress`、已孵化缺 `growth_value`、两套阶段不一致、旧异色布尔、未知或缺图物种、已放行宠物。检查进入、切换、跨阶段、刷新、图鉴、离开重进、云图失败和回退。阶段、余额或库存规则的改动另列范围和回归方案。

### D051 猞猁四阶段伪 3D

- 「森林」猞猁四阶段采用 260rpx 分层立绘。各阶段有独立身体、耳尖、眼睑、支点和静态兜底，共用短尾、动作和三个 S 级挂饰。独立 `pages/pet-preview/pet-preview` 仍提供成年四款对照。
- 使用内置 imagegen 以成年猞猁为参考生成幼年和少年透明主体。静态合成验证新增两阶段眼睑对位。代码编译和离线验证见 [CURRENT_STATE.md](CURRENT_STATE.md) 的 D051。
- PET-02 与 PET-09 的营地显示路径已修。初次加载和局部刷新复用云图解析，刷新保留选中 ID，局部更新同步宠物记录、轮播与档案，觉醒名取后端实际回执字段。PET-07 的稀有、异色标记已接到卡片，现有色相继续保留。历史图鉴和养成结算问题仍按原编号追踪。
- 营地 S 级以宠物 ID 在固定首批主题池中选一个主题。天赋、稀有度、颜色档仍独立。未新增数据库字段。先验营地实际尺寸、滑动切换、静态回退和真机性能，再定后续物种范围。
