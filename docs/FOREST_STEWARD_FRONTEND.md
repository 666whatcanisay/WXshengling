# 森林管家前端交付 · 2026-11-06

对应D032。用户明确“先把前端完成”，本轮实现原生小程序前端与现有只读接口衔接。没有实现或部署管理模型、LangGraph协作、审核/复盘服务，也没有上传发布小程序。

## 页面与可用路径

- AI首页：森林管家卡片位于“AI成长伙伴”上方；原规划师/教练/宠物聊天及折叠工具箱保留。
- 新页面：`miniprogram/pages/forest-steward/forest-steward`。沿用森林绿、木色、米白；当前目标条、成长循环示意、工作区提示、结果区域、折叠分工、本机需求草稿。
- 已有目标：调用现有`cloudApi.goals()`，用户主动选择，不默认取第一条。仅排除删除，完成/放弃等状态如实标注，支持重新进入续接上次选择。
- 今日安排：调用`cloudApi.tasks({date, goal_id})`，只显示所选目标在北京时间当天的任务、已完成/待完成数量和预计时长。无实际耗时/累计天数推断；打卡继续在原目标详情完成，返回管家重新读取。
- 需求交接：新计划需求按账号保存在本机，最多1200字；通过内存中的一次性账号绑定意图跳转AI Tab，填入原规划师，不自动发送/生成。保留已有会话和待确认发布；原输入框有未发送文字时，让用户选择保留或替换。原输入框maxlength同步1200，避免交接文本受默认长度限制。
- 本机记录仅包含选中goalId和新计划需求，不保存云端目标/任务快照、Key或完整聊天。不是服务端持久检查点，也不保证跨设备同步。保存失败给明确提示；登录缺失不读取目标。

## 接入状态与前端边界

| 区域 | 本轮实际行为 | 后续依赖 |
|---|---|---|
| 今日安排 | 现有接口的真实只读数据 | 真实微信端查看验收 |
| 规划师交接 | 填入原聊天输入框，原生成/编辑/发布流程保留 | 模型费用沿用原配置；本轮未测试调用 |
| 计划审核 | 展示职责、依据与“待接入”，明确没有审核结论 | 草案引用/版本、硬规则、Critic服务 |
| 复盘调整 | 展示所需记录、数据缺口与“待接入” | 有覆盖范围的事实包、主动反馈、分析与调整接口 |
| 协作分工 | 展示建议职责/可用状态，不展示虚构运行记录 | 管家决策、图运行状态和真实步骤事件 |
| 宠物/旧教练 | 原页面和处理器保留 | 宠物双向记忆/真实分析另阶段实现 |

成长循环是说明，不是进度条；分工列表不是实际调用轨迹。新页面目前没有管家模型对话、审核/总结/自动改任务或后台取消按钮。角色展示不等于最终角色数量/名称已定稿。

## 用户查看

在微信开发者工具点“编译”，进入“AI → 森林管家”。查看首页卡片、切换目标/今日安排、展开协作分工、审核/复盘状态；输入需求后转交规划师，确认文字出现且没有自动发送。回到管家检查所选目标与草稿续接。无需上传云函数；正式用户暂不会获得本地页面变化。
