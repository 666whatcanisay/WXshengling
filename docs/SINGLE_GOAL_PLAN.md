## 单目标路径与缺口

| 环节 | 当前可复用 | 实施前需解决 |
|---|---|---|
| 输入与澄清 | AI 页收集目标、周期、每日时间、基础 | 统一结构化约束与会话恢复 |
| 规划与确认 | 模型生成草案、编辑弹窗、ai_plans | 日期/阶段/时长校验；完整审核、修订与运行记录尚未实现 |
| 发布排程 | createGoal/createTask 与日期字段 | AI 固定 30 天且任务均落当天；发布逐条执行，失败仍可能提示成功；缺少服务端发布幂等与完整恢复机制 |
| 每日执行 | 首页、目标页、详情页均可打卡 | 重复奖励；各入口成长副作用不一致；前后端日期口径不同 |
| 进度与记录 | 完成标记、completed_at、成长日志 | 今日与周期进度混淆；详情页只看当天任务；历史统计未完整接通 |
| 复盘调整 | 报告骨架、教练入口 | 周报混用今日数据/示例；无完整未来任务调整链路 |
| 宠物反馈 | 成长池、养成、性格与互动 | 成长字段/图片刷新不统一；聊天为规则回复，未接真实上下文陪伴 |

本轮新增本地复现：同一目标含今日和明日各一项待办，完成今日唯一任务后，`completed_days` 仍为 0。原因：taskCheckin 查询同目标的所有日期任务，再判断是否全部完成。后续不能只改 AI 发布日期，否则会放大该问题。结果见 `goalCompletionWithFutureTasks`。

## 建议的实施次序

1. **底层一致性**：收紧已复现的管理员权限兜底，修正目标周期/业务日期与当日完成判断，统一任务奖励入口并处理重复请求。Key 由服务端使用，配置读取仅返回遮蔽信息。
2. **可确认的真实排程**：保存日期、预计分钟、阶段归属；计划发布使用统一后端入口、发布标识和明确的失败/恢复状态，避免逐条创建的半成功被显示为全部完成。目标详情能查看指定日期任务。
3. **分层 Agent**：管理、规划、审核、复盘按职责接入；限定工具、轮次、时长与 Token 预算；保存真实运行记录。LangGraph.js 的运行时/持久化兼容性先评估，采用与否单独讨论。
4. **记录与主动复盘**：代码统计指定时间段的计划数、完成数、未完成项与奖励；用户点击后让模型解释并生成调整草案。确认后只更新未来任务，保留已执行记录和调整版本。
5. **宠物陪伴与多目标**：先确定陪伴上下文与记忆深度；单目标链路可用后，再组织多目标共享时间预算。

各步范围以能支撑主线为准，不要求本轮补齐所有娱乐工具、Buff 或美术效果。

## 建议的模块和数据契约

- 模块：目标任务服务、事实统计服务、宠物/奖励服务、模型适配器、Agent 编排器。以接口隔开，先采用模块化单体。
- 目标候选字段：起始业务日期、周期天数、业务时区、每日时间预算；旧 target_value 按兼容方式处理，迁移前先核对线上数据。
- 任务候选字段：目标 ID、业务日期、阶段 ID、预计分钟、计划版本、完成时间；用户奖励由业务规则计算，模型不决定余额。
- 计划发布候选契约：草案 ID/版本 + 确认标识，返回创建结果和可恢复状态；同一确认重复提交应返回相同业务结果。
- Agent 工具：读取目标/统计、提交计划或调整草案；最终写入由有权限校验的业务服务执行。

字段命名、轻量重复规则和调整范围仍为建议，待结合工作量讨论；本轮不创建集合、不迁移数据、不安装框架。
