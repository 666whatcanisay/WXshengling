## 目标与“完成”的含义

让接手 Agent 能解释现有功能、页面、业务规则、代码路径、数据、素材、部署和实际行为，并能判断修改会影响哪些地方。不能承诺发现全部潜在 Bug，不能用“看完目录”“测试全绿”或理解百分比替代证据。

本轮重点是掌握当前作品；后续 Agent 产品功能仍按原有讨论另行推进。当前无需为理解项目先完成本地化迁移。

## 1. 真正的访问边界

- 模型服务的位置，与命令/截图工具在哪台机器运行，是两件事。本会话已实际读过用户电脑上的代码、执行本地隔离脚本并读取开发者工具画面。
- 这不意味着能直接读取微信/腾讯云私人后台。云资源需要可用网络、登录授权、资源权限和适配工具。
- 小程序 lzk 管理员只代表应用内权限，不等于开发者工具登录、腾讯云账号或云开发环境管理权限。
- 本会话尚未建立并验证完整云端取证通道，不能宣称云端版本、权限或素材已核验。
- 应优先使用现有官方命令/API或适配工具，能满足要求时不额外安装一批插件；无可用接口时再用已登录控制台界面；仍无法访问才请用户导出特定材料。
- 登录/扫码、平台授权等身份动作由用户完成。密码、长期主密钥不放进项目上下文或聊天交接包；不要求用户重新提供已说明的应用账号信息。
- 只读审阅与会写入数据的行为测试分阶段；后者先确定测试数据范围。一个管理员账号不足以证明所有普通用户和双微信账号隔离场景。

## 2. 人工最少需要配合什么

| 人工事项 | 原因 | 已有/待补 |
|---|---|---|
| 确认当前真正运行的项目目录、目标云环境、体验版/开发版 | 代码里的环境号未必是当前使用环境，部署版本可能不同 | 本地目录与配置已有，实际环境对应关系待确认 |
| 手动登录开发者工具、小程序和所需云开发平台，并完成必要授权 | 不能靠源码推导或绕过可信身份 | 已提供应用账号背景，登录后画面与云端检查通道待建立 |
| 确定可用于受控测试的数据/环境 | 打卡、喂食、灌注、发布计划会产生真实写入 | 当前只授权检查，不能自动拿正式宠物试破坏性操作 |
| 确认少量存在冲突的产品规则 | 代码只能告诉 Agent 现在如何做，不能证明原本想怎样做 | 保留现有风格已明确，周期/成长等仍有歧义 |
| 说明毕设题目、准确截止日、老师硬性要求 | 项目文件不能可靠推导这些外部约束 | 本科已知，其他待补 |

工具接入若需开发者工具的调试/自动化开关，应按实际版本检查，由用户手动完成必要设置。不能将模拟器自动化当成真机触摸、系统权限弹窗或微信身份验证的替代。

不要求用户逐条解释 18 页、手写数据库说明、截图全部后台或复制代码。Agent 应先自己取证，再只问确实缺失的项。

## 3. Agent 自己完成哪些事

### 第一阶段：建立静态全景

- 读取 AGENTS.md 与 docs 上下文，再枚举当前页面、组件、工具、云函数、脚本与旧文档。
- 逐项追踪页面入口、按钮/事件绑定、请求参数、云端 action、集合/字段、返回数据、显示与缓存。
- 标出无入口页面、未使用配置、遗留接口、模拟兜底、错误吞掉及重复规则。
- 输出“页面 → 操作 → 接口 → 业务 → 数据 → 反馈”的可查表，不只介绍功能名。
- 冻结审阅基线：记录日期、Git 状态与相关文件指纹，后续有变更只增量核对，避免把不同时间的实现混成一个版本。

当前已有部分成果，不从零重复。

### 第二阶段：核对云端实际状态

优先取得经授权的只读能力。根据环境和工具实际支持范围，读取：

- 目标环境与资源清单；login/app/init 实际部署包/版本信息、运行时、超时与配置入口。
- 本地与云端代码差异；不能下载代码时，用部署信息及受控行为记录标注验证限制。
- 集合清单、字段类型、索引、访问规则及必要的脱敏样本；不是下载全部个人数据。
- 宠物图片的实际文件列表、大小与可读性。
- 与被检查行为对应的近期日志和请求 ID，剔除密钥/敏感正文。
- 模型配置是否存在、端点与模型标识是否对应，不收集或在报告中回显完整 Key。

取不到哪一项就写明缺项，不能默认本地就是线上。

### 第三阶段：审阅全部宠物素材

- 对 15 物种×4 阶段的 60 个基础图片路径逐一获取并查看；保存至独立审阅目录，不覆盖现有资源。
- 检查可加载性、实际尺寸、透明边缘、完整轮廓、物种正确性、重复错图和四阶段身份一致性。
- 对同一基础图分别检查无滤镜、稀有度效果与颜色档位，定位“原图问题/改色问题/路径问题”。
- 输出每张图的状态与证据；录像中的三个样例不代表整个物种全部验收通过。
- 保留用户喜欢的现有形象；检查不是批量重生成授权。

### 第四阶段：受控运行验证

页面可自动操作时优先用经过兼容性验证的开发者工具调试/自动化通道；否则用桌面操作，再由用户补工具无法完成的真机动作。

至少覆盖：

1. 登录与身份 → 首页读取 → 目标创建/周期 → 任务创建与打卡。
2. 奖励入账 → 泉水 → 指定宠物灌注 → 孵化/跨阶段 → 图片刷新 → 重启后持久化。
3. 喂食/玩耍/抚摸、道具成功及失败、改名、觉醒、档案与图鉴。
4. AI 真实对话 → 草案生成 → 编辑 → 发布 → 真实任务日期/阶段 → 执行记录。
5. 情绪、日志、报告、统计、成就、胶囊和反馈的展示与数据来源。
6. 后台修改前后数据与前台一致性；角色/权限的有效限制。
7. 空数据、加载失败、重复操作、并发、切页、跨日、换身份与重启等边界。

模拟测试、开发者工具和真机结果分别标记。普通用户/双微信隔离只能模拟时，不写成线上已验。

每个场景记录：操作步骤、预期、实际、前后数据差异、相关代码、必要截图/日志和验证环境。不要只凭“成功”Toast 判断业务成功。

### 第五阶段：只向用户确认歧义

先做成“现在实现 A / 文档写 B / 建议选项 C”的简短对照，再请用户确认。

沟通校正（2026-10-28）：用户指出目标周期、喂食/互动/泉水、颜色/稀有度/天赋/Buff 已能从源码调查，不应先要求用户重新解释。必须先给当前实现及冲突证据，只有涉及后续选择哪条冲突规则时才讨论意图。

已可回答的现状：目标创建只自动生成当天一条任务，AI 发布将任务全部写到今天；本地代码未见完整每日重复/逐日排程。互动加宠物经验/亲密度，背包饲料加经验/成长，泉水扣池加成长；三套阶段判断冲突。颜色三档复用基础图，稀有度控制整图滤镜/装饰，天赋和物种 Buff 的实际成长/奖励结算未完整接入。这些不是必须由用户提供的技术信息。

优先讨论：

- 长期目标的周期与每日任务关系；漏做怎样处理。
- 宠物阶段由什么资源推进；互动与道具应如何影响它。
- 稀有度、颜色、天赋、Buff 分别应影响什么。
- 哪些形象/效果是用户喜欢、应保留的。
- 哪些历史数据经过管理员调整，哪些是自然运行产生。
- 毕设必须交付的内容与准确时间。

每轮只讨论几个真正影响判断的问题，不要求用户先重新讲完整项目。未经确认，不把代码现状当用户意图，也不把助手建议转成需求。

## 4. 最终交付与接手标准

复用现有 docs，按需补以下结构化证据，而不是反复增加重复概述：

| 交付 | 达到什么目的 |
|---|---|
| 功能覆盖表 | 18 个页面和全部发现的动作有去向；接口、数据、证据可追踪 |
| 云端快照/差异记录 | 说明实际跑的是哪份代码、哪些配置、与本地差别在哪里 |
| 宠物素材表 | 60 个基础素材逐项状态，区分原图与运行效果 |
| 规则与数据字典 | 解释 XP、成长、泉水、阶段、日期、权限等含义及冲突 |
| 验证记录 | 重要主链有操作和前后数据证据，可重复验证 |
| 问题/设计缺口/未知项清单 | 区分已正常、已复现问题、仅设计/展示、未启用、待核验 |
| 上下文入口与决策记录 | 新聊天读入口后能继续，不依赖跨聊天自动记忆 |

验收“理解程度”时，让 Agent 回答具体问题，例如：后台把宠物调成完全体后，哪些字段应改变，哪张图应加载，哪些界面需刷新，如何证明重启后仍正确。解释必须对应实际代码和运行证据。

所有已登记对象有状态及证据或未测原因、主链可复现、已知矛盾能解释，才称为“达到可接手开发的理解程度”。仍不承诺零未知或找到全部 Bug。

## 5. 降低人工成本的安排

- 用户先做必要登录/授权；Agent 先只读取代码、云资源与素材。
- Agent 自己建立功能/数据/素材清单，并汇总真正需要确认的规则。
- 用户确认少量规则及测试边界后，再做可重复的行为验证。
- 只为必须真机/第二微信身份/平台弹窗的场景请用户配合。
- 优先打通云端只读检查与一条端到端取证链；本地化和自动测试环境可后续逐步补齐，不必先整体重构。

### 7.2 按顺序推进的六步

| 顺序 | 用户配合 | Agent 工作 | 本步完成标准 |
|---|---|---|---|
| 1. 对齐环境与登录 | 在微信开发者工具打开当前项目；打开云开发控制台，完成必要扫码或平台登录，停在环境概览 | 从本地配置提取标识，检查现成 CLI/控制台通道，对照当前项目、目标环境、开发版/体验版；记录代码基线 | 当前查看的是哪个项目、哪个云环境、哪个运行版本有明确证据；取不到的版本信息单列 |
| 2. 云端只读核查 | 仅在身份验证、平台授权弹窗时操作；若确无读取通道，按 Agent 给的具体路径导出少量材料 | 查云函数部署信息、可取得的代码、集合结构/索引/访问规则、必要数据样本与近期日志；比较本地和云端 | 形成云端资源清单、差异和访问缺口；不以本地代码替代线上核验 |
| 3. 宠物素材检查 | 通常无需逐张操作；完成后只需指出少量必须保留的喜欢样例 | 读取 60 个配置路径，取得图片至独立审阅目录，做联系表；逐物种比较四阶段和运行改色效果 | 60 个路径均有“已查看/缺失/无法访问”等状态，正常与异常样例有证据，区分原图、路径、滤镜、刷新问题 |
| 4. 验证主要流程 | 先选定可写入的测试环境/对象；只补工具不能完成的扫码、手机动作或真机录屏 | 按下述三条主链记录操作、前后数据、请求结果、刷新及重启结果；能自动完成的操作自行完成 | 主链有可重复记录；每个关键动作能说明改了什么数据，而非只有成功提示 |
| 5. 其他功能与边界 | 只补无法独立观察的手机差异；第二微信身份不是前置要求 | 覆盖成就、情绪、报告、日志、胶囊、反馈、后台；异常、并发、跨日与身份场景优先隔离模拟 | 全部登记页面与动作有状态；没有条件实测的场景有明确未测原因 |
| 6. 对齐意图并交接 | 分批确认代码与文档冲突后真正影响后续改动的规则；补充老师硬性要求和准确交付日期 | 提供“当前行为—冲突证据—可选处理”的简短对照，更新功能、规则、问题和未知项 | 能说明哪些应保留、哪些是问题、哪些仅为设计；确认记录与助手建议分开 |

第一步需要用户实际完成的是：打开当前项目的云开发控制台并登录，停在环境概览即可。无需用户手抄环境号、数据库表或 18 页功能说明。身份验证可在后续需要时再做，不要求先把所有平台重新登录一遍。

### 7.3 运行验证的三条主链

| 主链 | 建议操作 | 必须留下的证据 |
|---|---|---|
| 目标与奖励 | 创建带明确周期的测试目标 → 查看自动任务 → 添加任务 → 打卡 → 再次点击 → 刷新/重启 | 目标周期、任务日期、完成状态、用户经验、泉水、日志的前后变化；重复操作是否重复发奖 |
| 宠物成长 | 对选定测试宠物互动 → 使用一件道具 → 少量分配泉水 → 查看阶段与图片 → 切页/重启 | 宠物经验、成长值、阶段、亲密度、背包、泉水、实际图片路径；不要求用正式宠物强行跨阶段，孵化/跨阶段先用隔离数据 |
| AI 到任务 | 使用已有配置提一个明确目标 → 对话 → 生成草案 → 编辑 → 发布 → 到目标页核对 | 是否真实请求模型或使用兜底、耗时、草案与落库任务的周期/日期/阶段/时长对应关系；记录失败结果，不伪造成功 |

AI 实测会消耗已有模型额度，发布和其他业务操作会写库，仅在确认的测试范围内进行。测试对象优先用已有测试环境；没有时，先做本地隔离验证，真实验证只使用用户允许的少量测试记录。不默认再注册当前微信，不默认新建收费云环境，也不把事后删除当作能完全还原奖励与统计。

只读阶段使用真正的资源/数据库只读查询，避免调用带副作用的业务接口。例如 `listAchievements` 会检测并写入解锁记录，不能仅因名为 list 就当作纯读取。删除用户、清理普通用户、放行喜欢的宠物、重置密码和清除模型配置不在正式账号上验证。

### 7.4 工具受限时的最少人工补充

- 电脑端能观察和操作时由 Agent 完成；确有阻碍时，明确指出受阻页面/字段，并请用户只导出那一项，不要求全面截图。
- 手机端只补上述主链中无法自动完成的部分，按单条链分段录屏。关键操作前后各停留约 2 秒，保留错误提示和刷新结果；Agent 自行抽帧、对照代码与日志。
- 第二微信/普通用户隔离无法实测时，明确标注为模拟或未测，不要求用户为“理解项目”立即准备第二身份。
- 模型 Key、密码等继续留在用户自己的配置或平台登录中，交接文档只记配置入口和核查结果。

建议把用户主动配合安排成三次：登录与环境对齐、必要的真机操作、规则确认。人工时间预算目标约 30～50 分钟，可分开进行；不包含平台故障、访问受限处理和 Agent 自行审阅时间，不能当成项目验收总耗时保证。

### 7.5 交付与停止条件

复用本文第 4 节列出的交付，不重复堆概述：功能覆盖表、云端差异、60 张素材状态、规则/数据字典、运行证据、问题与未知项。每个登记项至少有代码依据和状态，关键主链有运行证据；无法取得的部分保留缺项和原因。以这些条件判断可接手程度，不继续用 75%、90% 或 100% 代替验收。
