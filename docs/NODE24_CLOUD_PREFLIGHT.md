CLI授权可用，环境仍为用户已确认的cloud1-d5gz9j6zh654f4b36 / ap-shanghai。只有app/login/init三个Node16函数，目标副本名尚不存在；超时/内存与先前一致，无环境变量、层、触发器或VPC，有执行角色、公网开启。角色存在不代表其实际权限已验收。

逐个查得users/goals/tasks/ai_plans/growth_logs/user_growth_pool六集合均为PRIVATE，且均已存在。函数规则为排除匿名的登录用户可调用。具体计数与命令范围见 `audit/node24-cloud-preflight-20261104.json`，未查询密码或Key。

**需要配套收紧集合权限。** [官方权限定义](https://docs.cloudbase.net/en/api-reference/manager/node/rule)中PRIVATE允许创建者读写自己的记录，这也允许尝试绕过云函数直接改users.role/total_xp、池余额、任务完成状态及发布回执。此为配置和规则语义推出的风险，未做真实写入利用验证。前两轮对云函数入口的修复仍成立，但不能因此宣称数据库访问边界已完整保护。

当前miniprogram的JS未发现直接database/collection调用，数据经云函数处理，建议六集合改为ADMINONLY（仅管理端读写）。平台管理端与应用中的role=admin不同；该设置不是让所有应用管理员直接连库。改完先验证旧入口和新副本都能经云函数正常读取，再进入测试写入；发现兼容问题停止并按记录回退。

init含建集合/写预置成就副作用，不作为健康检查。创建init-node24前，仅合并 `"init-node24":{"invoke":false}` 到现有函数规则，其余规则保持原值；[具体函数规则优先于通配规则](https://docs.cloudbase.net/cloud-function/security-rules)。管理端调用不受客户端规则约束，因此CLI同样不调用init。以上规则调整本轮均未执行。
