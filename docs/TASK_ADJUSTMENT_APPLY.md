## 体验与契约

- 森林管家 → 选择目标 → 复盘调整 → 既有草案对照下方：“仅检查规则”“确认应用到N项未来任务”。未保存修改、冲突、旧来源、处理中、已取消、0变更、规则错误均不能应用。
- 弹窗展示当前版本、任务变更摘要及数量；取消弹窗不发送应用请求。更长草案仍应先查看完整对照，弹窗摘要有长度上限。
- 先把确切run_id / expected_revision / confirmation保存在本机，再调用applyAdjustment。confirmation覆盖运行ID、来源指纹、草案版本、要求、变更；不接收客户端新的任务内容或奖励值。
- 应用成功显示版本/数量和云回执，原对照保留为历史只读；刷新后不以“来源已变化”错误覆盖成功结果。按任务ID对应原安排，避免用户移除第一项建议后其余对照错位。
- 超时/丢响应保留原确认，禁止换稿、生成、恢复副本；只查询getAdjustmentApplication，或用户主动重试同一确认。applyAdjustment不走通用网络自动重试。查询暂无回执不等于失败；用户可取消协作以关闭与在途应用的竞争，若应用已提交则返回既有成功结果。
- 云端applicationSupported控制新按钮；旧云端仍可用草案功能，不提示用户调用尚未部署的新接口。

规则检查、查询、保存、取消和应用均不调用模型。只有原生成/主动语义审核仍按5A的费用边界调用模型。

## 已知并发边界

本轮没有改造所有旧app、后台和其他任务写入口为统一目标版本锁。预读之后插入全新任务ID属于查询幻影，或者事务快照之后并发写入仅读的反馈/历史资料，不保证全部串行化拒绝。每日预算是当前已读单目标窗口的检查，不是全账号强约束。相关真实并发及性能仍待云端验收；不能把本地模型的冲突检查当作全局锁已实现。若以后需要此级别一致性，应单独设计覆盖所有写入口的目标版本协议。
