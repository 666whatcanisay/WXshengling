# 森林管家首条协作链 · D038

日期：2026-11-06。用户在独立审核师正常联调通过后要求“继续推进”，本轮为管家首条真实协作链。**本地实现与隔离验证完成，用户明确批准后已部署并下载全包核对，已有稿/新需求/用户重进继续及等待确认时取消的正常验收完成。** 不把此次授权扩展为整套多Agent或所有云端写入测试。

## 能看到什么

入口“AI → 森林管家”，沿用原工作区、目标/今日任务、专业角色跳转和需求草稿。新增：

1. 根据新需求生成草案：管理协调 → 规划师生成并保存草案 → 代码规则 → AI审核 → 等用户查看/修改/确认。最多一次规划、一次语义审核；字段问题明确时先停下，不调用语义模型。
2. 检查当前云端草案：管理协调 → 规则 → AI审核 → 等确认，规划步骤标记“本次跳过”；同版已有审核复用，无需重复模型调用。
3. 页面显示真实步骤和已记录状态、当前草案版本、规则计数、模型建议、失败及继续/取消入口。已有正式目标和今日任务仍独立读取，运行草案不冒充正式目标。
4. 跳转原审核师时读取最新云端草案；已有本机未保存修改/待确认发布优先保留并明确提示，用户可通过原恢复/备份入口处理。

管理层首版是**代码驱动的流程协调**，不是额外管理模型聊天。规划师和审核师仍是各自独立能力，原规划师聊天/生成/发布入口保留；无自动发布。本轮先到首次审核和人工修改确认，不包含模型自主派单、自动一轮修订、教练复盘、宠物共享记忆或完整管理后台。这些按阶段再讨论，不冒充已经实现。

## 技术选择与旧假设复核

采用LangGraph.js **1.6.1**有界StateGraph，@langchain/core **1.3.4**、checkpoint **1.2.2**锁定。图和保存器用TypeScript，esbuild **0.28.2**生成Node24 CommonJS产物，当前2,709,710字节；编译产物无外部npm依赖，云端沿用原wx-server-sdk，不搬实验目录/SDK升级或Agent Server整套。

相比此前“优先独立异步执行器”的候选，本轮首条链选择**前台分段执行、持久暂停恢复**：每次native调用最多发起一次模型请求，在管理/规划/规则后保存检查点并返回；前端在页面可见时依次推进。关闭页面不再发后续步骤，当前调用可能继续完成，重进只查询，用户主动点继续。界面明确这一边界；不使用未await Promise假装后台，不承诺无人值守完成。

原因：当前app-node24为Nodejs24.11/30秒/256MB，规划/审核已有单次接口，用户要先完成可用协作体验；分段可先复用当前环境，避免为尚未确认的后台需求引入worker、队列、鉴权密钥和额外资源。后续若要求页面关闭后整条链继续执行，再独立验证可信服务端派发/执行器，而不是把前端推进描述为后台保障。18秒是模型绝对截止，仍不保证慢数据库下每步一定在30秒内结束，云端耗时/冷启动待限量实测。

### 检查点为何未直接用旧实验的CloudBaseSaver

实验适配器0.0.24通过了JSON文件替身，但直接依赖完整AG-UI/agents等包，接口使用`@cloudbase/node-sdk`的set形状和where排序/分页，当前业务为wx-server-sdk、事务只支持doc。在真实保存器适配未验收前不照搬实验结果。

本轮实现窄范围`ForestSaver extends BaseCheckpointSaver`：沿用框架序列化、pending writes及排序契约，通过注入端口使用既有wx SDK的doc事务。不是复制第三方保存器源码。只支持本图的单命名空间、有限祖先遍历（最多100），不提供用户删线程/任意筛选接口；不做通用多子图平台。后续API/包升级须同步运行恢复测试。

数据继续在既有ADMINONLY的`ai_plans`，`kind=forest_state`，原生openid+logical_id哈希定位文档，payload区分当前运行head、运行状态、检查点head、不可变检查点和中间写入。无需新集合/索引/权限。生成来源仍用`plan_generation`，带`steward_run_id`，不允许客户端通过旧aiDoGenerate接口绕过协作锁执行；真正生成复用原函数和草案store。

## 可靠性与费用边界

- 只信任云函数原生身份；请求内openid、图状态、节点名、Key和模型配置不作为可信输入。模型Key由服务器原适配器取出，不进检查点、运行回执或前端。
- 开始请求ID去重、同账号进行中协作互斥；每次推进有独立请求ID，网络层重试返回当前回执，不能意外推进下一步。最多20次实际推进/恢复领取，图递归有限，不提供任意节点执行入口。
- 节点有持久业务回执；模型结果/节点结果已落库而图保存失败时，恢复复用已保存结果，避免重复收费。生成请求ID确定，确认失败/未知的原模型调用不会自动重新发送；修好配置后用户可明确开始新协作。不是供应商账单恰好一次保证，失败/超时可能仍计费。
- 每步60秒租约和随机fencing token。未过期的并发推进只读取running；过期后主动恢复，旧token不能再写检查点/节点状态。取消使token失效；生成保存草案还在同一事务里检查取消/当前token及原草案版本，晚到结果不能覆盖当前稿。
- 规划开始日期在该协作的服务端生成记录固定，跨日恢复不会改写原请求日期；原独立规划流程的日期行为保留。
- 审核继续绑定draft ID/revision/指纹/要求/规则版本；外部编辑使旧运行结论失效，不能自动采用旧结果。发布始终走原页面/原事务，不因“等待确认”而自动写正式目标、任务或奖励。
- 记录有单文档400KB上限，中间写入100条、本图节点数固定；历史运行/检查点首版不自动删除，保留策略待后续实际使用量评估。保留不等于无限容量承诺。
